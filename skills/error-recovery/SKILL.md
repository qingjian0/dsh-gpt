# 故障恢复

## 故障处理顺序

1. **保留现场**：记录原始错误、时间、版本、提交 SHA、输入摘要和已发生副作用。
2. **分类**：区分参数错误、权限错误、环境问题、依赖问题、逻辑缺陷、外部服务故障和超时。
3. **定位**：根据堆栈、日志和最小复现确定失败边界；不要仅凭错误表象改参数。
4. **形成假设**：每次提出一个可证伪的根因假设，并指定验证方法。
5. **最小修复**：只修改与根因有关的部分，保留可回滚点。
6. **回归验证**：先复现旧故障，再验证修复，再跑相邻功能测试。
7. **更新状态**：说明根因、修复、验证证据和未解决风险。

## 重试策略

- 仅对明确可重试的瞬态错误重试。
- 指数退避并设置次数上限（若执行环境支持）。
- 非幂等写操作先查询状态，避免重复提交。
- 权限拒绝、Schema 错误和确定性逻辑错误不应盲目重试。

## 停止条件

达到重试上限、缺少权限、出现数据损坏风险、证据互相矛盾或无法安全回滚时停止，并报告需要的人工决策。
