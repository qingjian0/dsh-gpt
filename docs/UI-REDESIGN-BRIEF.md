# DSH-GPT UI 重做需求

## 现状问题

1. **6 个 tab 里 2 个是纯占位符**（Agent、定制），全是「待接入」「计划支持」
2. **真正做好的功能没有入口**：
   - MCP 123 个工具（GitHub 91/网页读取/连接器）—— 无 UI
   - 工具调用（function calling 模拟）—— 无 UI
   - 限流状态查询 —— 无 UI
   - 会话复用状态 —— 只有原始 JSON
3. **信息密度失衡**：API 页堆了 8 个输入框，Hook 页直接甩原始 JSON 文本
4. **没有状态可视化**：用户不知道「现在能不能用」「额度还剩多久」「刚才那次为什么慢」

## 设计风格

对齐 OpenAI 官方 App：
- 背景 #FFFFFF / 暗色 #212121
- 卡片 12-16dp 圆角，无边框，靠 2-4dp 阴影分层
- 主色用 OpenAI 绿 #10A37F 或黑 #0D0D0D
- 标题 Inter/SF 风格粗体，正文 15-16sp
- 大量留白，一屏一件事
- 图标线性 24dp，Material Symbols Outlined

## 建议的信息架构（4 个 tab）

### 1. 状态（Status）— 替代现在的「首页」
一张主卡片显示「现在能不能用」：
```
┌─────────────────────────────┐
│  ●  正常运行                 │
│                             │
│  模型     gpt-6-mini        │
│  延迟     3.7 s             │
│  额度     还剩 1800 秒       │
│                             │
│  [ 复制接入地址 ]            │
└─────────────────────────────┘
```
下面三个小卡片：Hook 状态 / API 状态 / 今日用量

### 2. API — 收发一体
上半部分：接入信息（地址 + Key，一键复制，默认折叠）
下半部分：**实测延迟图表**（最近 10 次请求的耗时条形图）
折叠区：上游配置（token/did/connector/临时对话）

### 3. 工具（Tools）— 全新，替代「对话」
这是最需要的新页面。三个子 tab：

**工具列表**
```
搜索框
─────────────────────
GitHub                    91
  get_repo                0.7s
  list_repositories       1.2s
  fetch_pr                1.9s
网页读取                   1
  打开任意 URL            0.6s
OpenAI Platform            6
─────────────────────
```
点进去能直接调用，看到返回结果。

**网页读取**
输入框 + 「读取」按钮，下面是阅读器样式的正文（带行号）。

**调用历史**
最近调用的工具、耗时、成功/失败。

### 4. Hook — 保留但重做
- 顶部：动态规则的数量和最近应用时间（人话，不是 JSON）
- 规则编辑器：表单形式（类名/方法名/模式/参数）
- 折叠区：原始观察报告 JSON（给调试用）

## 去掉的

- **Agent tab** —— 全是占位符，删掉
- **定制 tab** —— 全是占位符，删掉
- **对话 tab** —— 合并进「工具」或去掉

## 核心交互原则

1. **默认只显示结论**，细节全部折叠
2. **任何状态都能一眼看出能不能用**（绿点/黄点/红点）
3. **任何操作都有即时反馈**（按钮 loading、结果 toast）
4. **错误信息说人话**：不说 `rate_limited`，说「额度用完，还有 3 分钟恢复」

## 现有后端能力（可直接接）

```
GET  /health              服务状态
GET  /v1/models           模型档位（gpt-6 / -think / -deep / -search / -tools）
GET  /v1/mcp/tools        123 个工具 + schema
GET  /v1/mcp/resources    17 个连接器
POST /v1/mcp/call         {name, arguments}
POST /v1/web/open         {url}
GET  /v1/hook/status      Hook 状态
GET  /v1/hook/events      Hook 事件
POST /v1/chat/completions 生成（会消耗额度）
```

限流状态在生成接口被限时返回 429 + `retry_after_seconds`。
