# 软件工程

## 仓库理解

1. 确认仓库、默认分支、当前分支、工作区状态和目标版本。
2. 阅读项目说明、贡献规范、架构文档、相关源码和测试。
3. 追踪真实调用链与数据流；不要只根据文件名推断行为。
4. 检查现有实现和历史约束，避免重复造轮子或覆盖用户改动。

## 实现策略

1. 先定义可复现的问题或验收目标。
2. 选择最小、局部、可回滚的补丁。
3. 保持模块边界、公共 API、命名和错误处理一致。
4. 对配置提供 Schema、默认值、边界校验和兼容策略。
5. 新增行为必须有测试；修复缺陷必须增加回归测试。
6. 更新 README、配置示例和迁移说明。

## 验证

- 先跑最小相关测试，再跑完整测试。
- 执行格式、类型、静态检查和构建（项目提供时）。
- 检查 diff、意外文件、依赖变化和敏感信息。
- 对外部服务或真实宿主集成，明确区分模拟测试与真实验证。

## Git 纪律

- 遵循用户指定分支；未经授权不合并、不推送到稳定分支。
- 修改同一路径必须串行更新并使用最新文件版本。
- PR 描述写清动机、实现、验证、限制和风险。
- 不因 CI 通过就宣称真实运行环境已验收。
