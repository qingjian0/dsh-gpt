# Hook UI 信息架构与验收规范

## 产品目标

Hook 页面应成为完整的运行控制台，不是 JSON 编辑器，也不是只有三个数字的简陋状态页。用户需要一眼知道：
1. 当前有哪些内置 Hook 组件和动态规则；
2. 每个 Hook 具体挂载了什么类/方法、做什么事；
3. 哪些只是配置，哪些已下发、已安装、已触发，哪些失败；
4. 发现能力能找到什么、观察能力记录什么；
5. 哪些功能属于旧版参考实现，当前 APK 尚未集成。

## 一级 Hook 控制台

采用分区卡片和可搜索列表，避免把所有详情塞进一屏。

### 顶部状态区
- 动态 Hook 总开关（明确标注只控制动态规则）。
- 目标包名、模块注入状态、最近目标进程报告时间、配置 revision。
- 状态标签：已注入/最近报告已过期/未检测/控制接口不可用。
- 手动刷新；进入页面自动读取状态；页面可见期间定时刷新。
- 不得将“历史报告存在”显示为“当前在线”。

### 总览指标
- 内置 Hook：已安装 / 尝试数 / 失败数。
- 动态规则：已配置 / 已启用 / 已安装方法 / 已触发规则。
- 发现：类数量 / 方法元数据 / 最近扫描时间。
- 事件：缓冲事件数 / 最近事件时间。
- 请求抓取：开关状态（明确标注可能含敏感数据）。

### 内置 Hook
按设备信息、系统属性、文件检测、命令执行、包查询、调试检测、证书校验、遥测调用分组。
每个目标方法逐条显示：
- 功能名称和实际目标类/方法/字段；
- 作用说明；
- 当前配置状态；
- 运行时安装结果（成功/失败/未匹配/未检测）；
- 失败原因。
不能只显示“硬化已启用”一个布尔值。

### 动态 Hook
- 搜索/过滤：类名、方法名、状态、模式。
- 每条规则显示类名、方法名、模式、启用状态、安装方法数和调用数。
- 支持新增、编辑、复制、启用/禁用、删除。
- 规则编辑用表单：类名、方法名、参数类型或 JVM descriptor、模式、采样频率、必要参数。
- 行点击进入详情页，显示完整方法签名、匹配重载、安装记录、调用统计、失败诊断、最近事件。
- 提交后展示“已保存/等待目标应用用新 revision 应用/已应用/部分失败”，不能直接 toast“已生效”。

### 类与方法发现
- 类名关键字/前缀/精确类名搜索。
- 最近启动扫描结果。
- 扫描任务状态、耗时、DEX 数、扫描类数、成员数、分页、截断原因。
- 类详情分栏：声明方法、继承方法、构造器、字段（仅元数据）。
- 选择成员后生成候选规则，进入规则编辑确认；不直接自动执行。

### 事件中心
- 按时间、规则 ID、类名、方法名、事件类型筛选。
- 显示耗时、异常类型、序号和时间。
- 默认不展示/不采集参数、返回值、请求头、Cookie、Token、请求体。
- 事件缓冲容量、清空记录、导出脱敏元数据。

### 高级设置 / 诊断
- 类加载监听开关及计数。
- 采样率和事件上限。
- 请求抓取独立开关、敏感信息警告、日志清理。
- 配置 revision、应用报告、最近错误、模块日志。
- “旧版未迁移能力”折叠区，明确不属于当前 APK。

## 二级页面

1. **内置 Hook 详情**：每个目标方法、安装状态、功能说明、风险提示、失败原因。
2. **动态规则详情/编辑**：配置与真实运行清单对照。
3. **类详情**：成员元数据和候选规则。
4. **事件详情**：元数据事件。
5. **扫描任务详情**：进度、限制、结果分页。
6. **诊断详情**：报告 JSON、日志、配置版本和错误码。

## 视觉与交互

- 采用 Material 3，统一卡片、分组标题、图标、状态色、信息层级。
- 搜索、筛选 Chips、分段页签、展开详情、空状态、错误状态和加载状态。
- 首屏突出“现在有哪些 Hook 在工作”，而不是说明文字。
- 每个功能都有状态和来源；未实现/旧版参考用灰色“未集成”，绝不伪装成可操作开关。
- 所有按钮都要有实际动作和 loading/结果反馈。
- UI 只显示后端确认的数据；不造示例数字，不猜安装结果。

## 实施优先级

P0：真实清单协议（内置 Hook 逐项安装记录、动态规则状态、最近报告时间）和首页信息架构。
P1：动态规则 CRUD、方法发现、候选规则编辑。
P2：事件中心、扫描分页和诊断。
P3：请求抓取独立设置/清理，以及旧版能力差异说明。
P4：真机验收：模块注入、内置 Hook 安装清单、动态规则热更新/撤销、进程重启、离线/过期状态、事件回传。

## 验收标准

- 用户能看到所有当前 APK 内置 Hook 的实际目标，而不是只看到规则总数。
- 用户能看到全部动态规则和每个规则的真实安装方法。
- 不存在把旧版 `gpt-hook/` 说成当前已运行功能的情况。
- 目标进程没有上报时，本地配置列表仍完整显示。
- 报告过期不显示在线。
- 动态总开关不会被描述为关闭所有内置 Hook。
- 安装失败能定位到具体规则/目标方法和失败阶段。
- 所有发现结果明确标注分页与截断。
- CI 通过，并完成目标设备验证后才标记已交付。
