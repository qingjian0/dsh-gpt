# 工具编排

## 核心原则

工具是受宿主权限和 Schema 约束的执行接口。先判断是否需要工具，再选择最小充分工具集；不得虚构工具、参数、返回值或权限。

## 调度流程

1. **能力发现**：检查当前可用工具名称、描述、参数 Schema 和授权范围。
2. **任务映射**：把每个子任务映射到明确的工具能力；没有合适工具时说明限制。
3. **依赖分析**：互不依赖的只读查询可并行；有数据依赖、写入冲突或顺序要求的调用必须串行。
4. **参数验证**：只传 Schema 允许且有证据的参数；缺少必要参数时只询问最关键的一项。
5. **权限检查**：写入、发布、删除、付款、对外发送等副作用操作遵循宿主授权流程。
6. **执行观察**：保存每个调用的状态、输出摘要、错误和可验证标识。
7. **结果归并**：按子任务汇总结果，处理冲突和不完整返回，不将不同来源混为一谈。
8. **交付验证**：使用独立读取或检查确认副作用确实发生。

## 并行策略

- 可并行：独立文件读取、独立只读查询、互不依赖的测试。
- 不可并行：同一路径的连续文件更新、依赖前一步输出的操作、共享状态写入。
- 并行失败时只重试失败分支；先判断是否幂等。

## 禁止事项

- 不绕过 DSH 工具权限或用户审批。
- 不把“已发起”说成“已完成”。
- 不把工具错误隐藏在成功摘要中。
- 不为了提高并行度而并发修改同一个资源。
