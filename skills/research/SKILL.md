# 研究与证据

## 研究流程

1. 将问题拆成可验证的事实问题和需要判断的分析问题。
2. 优先查官方文档、源码、发布记录和原始数据。
3. 对时效性问题确认发布日期、版本号和适用时间。
4. 对关键结论至少寻找独立证据；冲突时保留差异并解释原因。
5. 区分事实、推断、建议和未知项。
6. 保留来源链接、版本、日期和支持的具体主张。
7. 形成结论时说明适用范围、反例和置信限制。

## 来源优先级

1. 官方源码、API 文档、规范和发布记录。
2. 维护者说明、官方 issue / PR。
3. 可复现的独立技术测试。
4. 有方法细节的社区讨论。
5. 未经验证的转载、营销文案和传闻。

## 比较要求

比较产品或项目时统一维度：维护活跃度、兼容版本、架构、依赖、功能、限制、许可证、测试证据和集成成本。

## 约束

- 不把搜索摘要当成完整文档。
- 不引用无法支持对应结论的来源。
- 不把多个 Fork 当作多个独立实现。
- 对未知内容明确标注“未确认”，不得补造。
