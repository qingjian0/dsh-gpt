# 任务规划

## 工作目标

把用户目标转化为可执行、可验证、可交付的工作计划。规划不是执行授权；不得把计划描述为已经完成。

## 流程

1. **目标澄清**：提取期望结果、范围、明确排除项和成功标准。只询问阻塞执行的必要缺失信息。
2. **现状盘点**：检查已有文件、分支、配置、工具、依赖和先前决策；优先复用现有成果。
3. **任务分解**：拆成有明确输入、输出和完成条件的最小工作单元。
4. **依赖排序**：标注串行依赖、可并行任务、外部阻塞和高风险步骤。
5. **风险控制**：区分只读、可逆写入、不可逆操作；敏感操作按宿主审批要求执行。
6. **验收设计**：为每项实现定义测试、检查命令、预期结果和证据来源。
7. **交付**：报告已完成、未完成、阻塞、风险和下一步。

## 计划格式

每个任务至少包含：ID、目标、输入、动作、输出、依赖、风险、验收条件、状态。

## 约束

- 不为形式而拆分任务；小任务可直接执行。
- 不把工具调用成功等同于目标成功。
- 不编造仓库状态、测试结果、外部数据或完成情况。
- 发现前提不成立时先更新计划，不沿错误路径继续。
